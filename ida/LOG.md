What the first auto-analysis had wrong, measured on scratch copies before changing anything:

- **Both Players: the IAT the code uses was never recognised.** VMProtect moved the import directory and a second IAT into `.vmp1` (IDA named that one), but `.text` still calls through the linker's IAT at the start of `.rdata` (PLAYER `0xaa1000`, PLAYER_1015 `0xa9f000`). Its slots still hold their `IMAGE_THUNK_DATA` in the file (hint/name RVAs such as `0x8e6cb0`, or ordinals). IDA read 1,899 of those RVAs as offsets into `.text`, resolved `call ds:[slot]` and `call reg` to them, and built garbage functions there (PLAYER `0x8e5f40-0x901b10`, PLAYER_1015 `0x8e3b80-0x8ff550`, about 113 KB each). All 18,710 + 674 `call/jmp ds:[...]` sites in PLAYER went through unnamed slots.
- **Both Players: text$x was misread.** No `__CxxFrameHandler3` name, so unwind funclets and handler stubs were not attached to their functions. PLAYER had 5,562 of 6,340 stubs as stand-alone `SEH_` functions (from a FLIRT signature); PLAYER_1015 had 6,191 of 6,336 stubs and 17,677 of 18,069 funclets as `dd` arrays. That, not missing code, is the 5,671 gap between the two Players.
- **All three:** functions referenced only from data were code without a function (vftable slots, static initialisers, atexit thunks), destructors reached only by `jmp` from unwind funclets were tail chunks of some caller, and catch blocks sat outside their function.
- STUDIO needed no import or EH repair: IDA had already made 30,105 of 30,116 funclet/stub extents tail chunks there. That is why it had fewer "functions" than the Players despite a larger `.text`.
