## Patterns proven

- **An unread `std::list<T>` instantiation can rename an ICF-folded template body that App already marks.** Our
  `list<rbx::signals::connection>::_Buynode` (InstancePacketCache) folds with `list<linked_streambuf*>::_Buynode`.
  Network links before boost_static/App, so the folded address gets the connection name. App's Util/Http.h
  TEMPLATE rows (PLAYER 0x005e7920, STUDIO 0x006d13d0) then stop pairing, and STUDIO loses 0x006d13d0 and three
  callers (chain_base 0x0068db20, the GuiService list ctor 0x00859be0, the map 0x0085c890). A second TEMPLATE
  marker at the same address is dropped as a duplicate (reccmp parses App's file first). So the connection list
  stays undeclared, with a placeholder, until Http.h's namerefs change (see Unresolved).
- **Virtuals of a non-primary base are compiled with that base's `this`.** Replicator::OnInternalPacket (PluginInterface2,
  +0x1094) reads Replicator+0x1a08 as `[this+0x974]`, and terrainCellChanged (CellChangeListener, +0x10a4) reads
  clusterDebounce as `[this+0x109d]`. Subtract the base offset before mapping members.
- **An inline ctor/virtual in a header is emitted only where it is used.** The original instantiates
  ProcessPacketsJob's ctor and sleepTime from Replicator::onServiceProvider. Without a caller, no COMDAT exists to
  pair. A STUB caller that constructs the object is enough, and the ctor stays out of line under /Ob2 (260 bytes,
  EH).
- **A dead `push 0` / `mov [esp],0` in getRakStatsString** comes from `rakPeer ? &stats : NULL` passed straight to
  `StatisticsToString`. Writing it as a ternary in the call reproduces it.
- **ClusterReplicationData ctor 0x005a0090: unsolved.** The original stores 0x2c, 0x28 (0x1000000), the bitfields,
  0x0c, 0x30. Our compile puts the bitfield `and` first and the 0x28 store last, whether 0x28/0x2c are in the
  init list or the body and whatever the body order. 0x28 is probably not a plain int.
