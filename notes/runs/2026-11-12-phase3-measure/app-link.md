# app-link (workflow phase3-measure, wf_271afd88-e3a)

The imported App tree now links into both exes, and `OGRE_PRIOR_APP` defaults to ON. `build/` is configured that way and holds the linked exes, PDBs, maps, `<exe>.link.log`, Log.dll, boost.dll and tbb.lib. The CSVs in reccmp/ are regenerated against this build. The Sweep agent can use it directly: `cmake --build build`, then run reccmp from build/.

**Unresolved externals, stubs, and how call sites pair**
- **Unresolved:** each exe has 40 unique unresolved symbols (627 LNK2001 + 19 LNK2019 references). The only link warnings are 2 × LNK4088 (/FORCE).
- **Stubs:** 3 per target, generated by the new `tools/gen_link_stubs.py`.
  - PLAYER: `RobloxExtraSpace(RobloxExtraSpace*)` 0x00874f40, `~RobloxExtraSpace` 0x008766a0, `RBX::Log::writeEntry` 0x009b1890.
  - STUDIO: 0x00924c30, 0x00926390, 0x00a68980.
- **How a stub is wired:** I used option (a), but each stub is an `extern "C"` STUB function bound to the caller's decorated name by `#pragma comment(linker,"/alternatename:...")`.
  - It needs no header knowledge.
  - It can never collide with a real definition: the alias only applies while the symbol is unresolved.
  - `STUB()` stores a distinct constant, so ICF cannot fold two stubs. `check_folded` reports 0 problems.
- **Verified:** `RobloxExtraSpace::constructChild` (0x00875050) calls the 0x00874f40 stub and scores 100% under `--verbose`. Its call target was 0 under /FORCE alone.
- **The other 40 stay on /FORCE:UNRESOLVED.** The list with reasons is in `Client/_generated/<t>/unresolved.txt`:
  - 20 are data: 15 FLog log-group bytes plus FFlag::MarkRakNetSocketOnDelete, Tokens::apiToken, Log::provider, Security::rbxTextBase/Size.
  - 15 have no address in the original: CSHA1, PacketizedTCP and TCPInterface (the original dropped them), XmlParser's constructor, ProtectedString::getSalt, a Reflection convert template, `RobloxExtraSpace()`, and `FLog::RegisterFlag` with `FLog::FastVarType`.
  - 4 could not be parsed: three LZ4 C functions and slot_exception_handler.
  - 1 is already claimed: TextXmlParser::parse has a marker but its body is not compiled.
- **Generator safeguards:** it skips addresses another marker or a CSV row already owns. A name-only match is not accepted: it had wrongly put `RobloxExtraSpace()` on the parent constructor. It is incremental, and a rerun gave the same result.

**Denominator and CSVs**
- function-size has 40,472 PLAYER rows and 42,330 STUDIO rows. That is +223 and +213 over DECOMP_PLAN's 40,249 / 42,117, from ida-prior's thunk splits.
- symbols.csv went 6,387 → 6,419 (PLAYER) and 6,503 → 6,514 (STUDIO). The generator now includes `prior:` names.
- libdata.csv went 770 → 859 and 663 → 760. It now skips addresses a Client/ marker owns, so stub targets are not relabelled as library.

**What changed to get it linking**
- **Flags:** probe-libs' proven flags are in CMakeLists.txt, each with its deciding address. What is still unproven keeps `# TODO prove`.
  - Base, AppDraw, RbxG3D, RbxOgre and GfxAdapters use `/Oy`.
  - GfxBase uses `/Od`.
  - The shells use `/GS /fp:precise /GL` with no `/arch`, and the exes link with `/LTCG`.
  - Log uses `/Oy /GS /GL` with no `/arch`.
- **Log.dll** is now its own SHARED target, and both exes import it.
- **tbb.lib** is generated from the shipped tbb.dll's export table by the new `tools/dll_implib.py`. TBB's headers auto-link it.
- **Three App TUs** (ScriptContext, ThreadRef, LuaInstanceBridge) get the prior tree's full `RobloxExtraSpace` through a source-level include directory.
- **The prior globs** no longer re-add raknet/ or g3d/. That was the GImage_png.cpp failure.
- **The exe link lines are about 40 KB,** past Windows' 32,767-character limit; wine's link.exe then exits 1 with no output. So the exes are defined in `cmake/link/`, which forces response files for that directory only.
