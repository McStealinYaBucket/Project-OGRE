## Failures

- 0x005a8d90 `void RBX::Network::serialize<RBX::UDim>(RBX::Reflection::ConstProperty const&, RakNet::BitStream&)` (callgraph-guess): IN SAMPLE. In the 2016 Network/Streaming.h this is a free template, so it is cdecl: `ret 0` and ecx unused. The PLAYER body loads esi from ecx, reads one stack argument, returns that argument in eax and ends in `ret 4`. That is a __thiscall member that returns an aggregate through a hidden pointer, shaped like ConstProperty::getValue<UDim>() const. serialize<T> was inlined, and the callgraph pass named the callee.
- 0x008a4a50 `G3D::Color3* RBX::Lua::Bridge<G3D::Color3, true>::pushNewObject<G3D::Color3>(lua_State*, G3D::Color3)` (callgraph-guess): IN SAMPLE. pushNewObject is static, so cdecl `ret 0` with the 12-byte Color3 copied onto the stack. The body reads lua_State* from [ecx], takes Color3 through a pointer at [esp+4] (three movss loads), and ends in `ret 8` (Hex-Rays: thiscall(this, int*, int)). That is a member functor that inlined pushNewObject, not pushNewObject itself.
- 0x005844a0, 0x00584880, 0x005848f0, 0x005849d0, 0x00584a40, 0x00587700, 0x00587770, 0x005877e0, 0x005a8e80, 0x005a8f00, 0x005a9060, 0x005a9150, 0x005a91d0 `RBX::Network::serialize<T> / deserialize<T>(Property&/ConstProperty const&, RakNet::BitStream&) for T = Vector3, CoordinateFrame, bool, float, Color3, double, Vector2, Vector2int16, UDim2, Faces, Axes (13 rows; 0x005848f0 is callgraph mac:, the rest callgraph-guess)` (callgraph-guess): Same pattern as 0x005a8d90. Each body is `int __thiscall(this, int)` with ecx live and `ret 4`. A 2-parameter cdecl free template can only end in `ret 0`. These bodies are the out-of-line Property getValue/setValue<T> callees left behind when MSVC inlined (de)serialize<T>.
- 0x0083a150 `RBX::ChangeHistoryService::requestWaypoint(char const*)` (callgraph): Both oracles agree on this name. The body ends in `ret 28`, which is VC9 sizeof(std::string) passed by value; the parameter list expects `ret 4`. Both the oracles and the 2016 header have `requestWaypoint2(std::string name) { requestWaypoint(name.c_str()); }`. PLAYER's function is requestWaypoint2 with requestWaypoint inlined into it.
- 0x0076d1d0 `Ogre::Matrix4::makeTransform(Ogre::Vector3 const&, Ogre::Vector3 const&, Ogre::Quaternion const&)` (callgraph-guess): PLAYER imports exactly this function from OgreMain.dll (`?makeTransform@Matrix4@Ogre@@QAEXABVVector3@2@0ABVQuaternion@2@@Z`), so no body for it exists in the exe. The body also pops 8 bytes (2 arguments), not 12.
- 0x004805a0 `std::operator+<char>(std::string const&, std::string const&)` (callgraph-guess): PLAYER imports this exact overload from MSVCP90.dll (`??$?HDU?$char_traits@D@std@@...@0@ABV10@0@Z`). The body is also `int __fastcall(int)`: ecx is the only argument, `ret 0`, and nothing like two const& arguments plus a hidden return pointer.
- 0x0041bcd0 `rbx::any_cast<boost::shared_ptr<std::map<std::string, RBX::Reflection::Variant>>>(rbx::placement_any<RBX::Region3>*)` (callgraph): Both oracles agree on this name. The body is a constructor: it stores vftable 0x00aff904 (std::runtime_error) into [ecx], copy-constructs a std::string argument at +0xc, returns this and ends in `ret 4`. any_cast is a free function and would not use ecx.
- 0x0040a6a0 `std::_Rb_tree<std::string,...>::_M_erase(std::_Rb_tree_node<std::string>*)` (callgraph): _M_erase is a libstdc++ internal that has no Dinkumware counterpart (VC9's recursive node eraser is _Tree::_Erase(node*), `ret 4`). The body is __thiscall with 3 stack arguments and `ret 12`, the shape of erase(first, last) returning an iterator, not a 1-parameter function.
- 0x006f9cf0 `std::_Rb_tree<int, std::pair<int const, RBX::FriendService::FriendStatus>,...>::_M_erase(node*)` (callgraph-guess): Same as 0x0040a6a0: `ret 12` with 3 arguments, against a 1-parameter libstdc++ internal.
- 0x008a43f0 `G3D::Vector3int16* RBX::Lua::Bridge<G3D::Vector3int16, true>::pushNewObject<G3D::Vector3int16>(lua_State*, G3D::Vector3int16)` (callgraph): Both oracles agree on this name. Same shape as 0x008a4a50: lua_State* comes from [ecx], the value from a pointer at [esp+4] (dword plus word at +4), and the body ends in `ret 8`. The static function should be cdecl `ret 0`.
- 0x0082f030 `G3D::Array<RBX::SpanningEdge*, 10, 32ul>::resize(int, bool)` (callgraph-guess): An ordinary __thiscall (esi = ecx, nothing LTCG-like) that pops 4 bytes, so it takes one argument where the name has two. The body calls the allocator's vfunc with n*4 and stores the result at [this], which is G3D's private realloc(oldNum) shape. resize was inlined into its caller.
- 0x0041bdd0 `joinGameTeleport(std::string, std::string, std::string, NSObject*, boost::shared_ptr<RBX::Game>)  (_ZL, iOS-app static)` (string-unique): An iOS-app static that takes an Objective-C NSObject*, so it cannot exist in the Windows build. The pairing rested only on the generic URL fragment '?suggest='. The PLAYER body takes arguments in ecx, edx and 2 stack slots (`ret 8`) and does not fit the parameter list either.
- 0x00659170 `RBX::MacSystemUtil::getGPUMake()` (string-unique): MacSystemUtil is a Mac-only class (no such class or file in the Windows build). The body pops 4 bytes and does not read ecx, which a 0-parameter function would only do if it is static and returns through a hidden pointer. At best this is the Windows equivalent under a different class, so the name is wrong.

## Systematic causes

- The callgraph and callgraph-guess passes have no ABI gate. When MSVC inlined the oracle function, the one unpaired neighbour that is left (usually its out-of-line callee or caller) takes its name. This caused 21 of the 25 failures: (de)serialize<T> became Property::getValue/setValue<T>, requestWaypoint became requestWaypoint2, pushNewObject<T> went to a functor that inlined it, any_cast went to a runtime_error constructor, and Array::resize went to realloc. The report says arity cannot be checked because the PE export has no prototypes, but `ret N` plus ecx liveness can be read from the bytes and would have rejected all 21. Suggested gate: the candidate must agree with the parameter list, i.e. __thiscall pops params (+4 for a hidden return pointer); cdecl or variadic pops 0; D0 pops 4; a constructor pops params (+4 when the class has a virtual base).
- No check against PLAYER's own import table. A name that PLAYER imports from a DLL (OgreMain.dll: Ogre::Matrix4::makeTransform; MSVCP90.dll: std::operator+(string const&, string const&)) cannot be the name of a function inside the exe. Exception: D0 rows for exported Ogre classes are fine, because ??_G is emitted per module.
- No platform filter on oracle names. Apple-only entities are accepted: iOS-app `_ZL` statics with Objective-C types such as NSObject*, and RBX::MacSystemUtil. string-unique accepted joinGameTeleport on a generic string ('?suggest=') that is unique only inside iOS.
- libstdc++ implementation internals (std::_Rb_tree<...>::_M_erase, 4 rows proposed: 0x00403cd0, 0x0040a6a0, 0x006f6900, 0x006f9cf0) are proposed for bodies built with Dinkumware (VC9). Two are refuted by ABI. The other two can never be the real names of MSVC functions either, whatever the body is.
- Not a script error, but a limit on any ABI test: PLAYER contains LTCG objects with custom calling conventions. Player client code around 0x0044f380-0x00458f40 (CRenderSettings) passes `this` on the stack and ends in `ret 4`; Lua static functions (index2adr, subexpr, push_onecapture, luaI_openlib) take arguments in registers; 0x0041bdd0 uses ecx and edx; 0x0081fb50 uses eax and ecx. So a purge mismatch in those regions is uncertain, not wrong. My checker also needed tail-jump, noreturn and EH-funclet handling: funclet `ret`s in tail chunks and jmps to the 6-byte _CxxThrowException thunk at 0x009efe7c would otherwise have produced about 90 false rtti-slot failures.
