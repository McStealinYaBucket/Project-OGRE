# g3d-2013 (workflow phase4-pairing, wf_4baec7d9-68d)

I fixed the float-constant blind spot, added five measured G3D patches (0006–0010), and re-scored. reccmp now gives PLAYER 1,969 / 40,468 functions at 100% (1,928 before) and STUDIO 1,857 / 42,329 (1,815 before). Four entries that were at 100% dropped below it: one function and three vtables, see unresolved.

The STUDIO gain (+42) is the cleaner figure. The PLAYER gain includes about 60 RakNet functions that reached 100% because of another agent's change to `tools/msvc9/winewrap.py` (13:07) during my run, not because of my work.

**1. Matcher fix.** A shared check in `tools/lib/lua_match.py` (`consts`, `const_diff`) now compares the actual values of the string, float and double literals a function uses, wherever the masked bytes are equal. The lua, g3d, raknet and boost matchers all use it. Two rules keep it from over-rejecting:
- A `__FILE__` string counts as equal when only the build checkout path differs.
- Named const tables are not compared; that is data, which `reccmp-datacmp` already reports.

The same check now also narrows the search step, and the neighbour windows only count a file's own functions within its main address range. The name step also accepts the `match:` names that are now in `ida/exports/*-names.csv`. A runnable check is `python3 -P tools/lib/lua_match.py --selftest`.

Rows whose status changed because of the check (confirmed by re-running with the check switched off):
- **PLAYER, G3D:**
  - `Color4::one` at 0x007681b0 is dropped; that function loads 0.6f.
  - 0x009d7c30 was called `Color3::one` but loads 0.7f. It is now correctly `Color3::gray`, identical.
  - `Plane::toString` at 0x009e4c30 is dropped. The function there uses the string "Sphere(<%g, %g, %g>, %g)", so it is `Sphere::toString`, which keeps that address.
- **STUDIO, G3D:** the same three, at 0x007b3c50, 0x006aa6f0 and 0x006b9aa0.
- **Lua, RakNet, boost:** no changes. 96 identical RakNet rows in PLAYER are now checked by value.
- **Search and neighbour change:** newly located and identical are `Color3::red`, `green` and `blue` at 0x009d7980, 0x009d79c0 and 0x009d7a00, `Color4::clear` at 0x009db4e0 and `G3D::toLower` at 0x009e5fb0.
- **Not caused by the check** (the check-off run gives the same rows; the inputs changed after the old CSVs were written):
  - RakNet, in both targets: `PluginInterface2` virtuals (`OnPushBackPacket`, `OnInternalPacket`, `OnNewConnection`, scalar deleting destructor) dropped, its constructor added; `RakPeer::Set/GetMaximumIncomingConnections` and `ApplyNetworkSimulator` dropped.
  - Boost: `zlib_base::xdeflate`/`xinflate` added.
  - G3D: `MemoryManager::alloc`/`free` at 0x009daed0/0x009daee0 had stopped being located once the names CSV switched to `match:` names. Accepting those names restored them.

**2. G3D helpers that 2013 App code calls out of line.** `tools/lib/g3d_calls.py` counts every call from Roblox code into G3D. Patch 0006 restores upstream's out-of-line declarations, each confirmed in the PLAYER bytes:
- `Matrix3`'s copy constructor at 0x009d7f30: 315 calls in 237 functions. It folds with `Matrix3(const float[3][3])`. `operator=` stays inline, as 0x007254de shows (an inline `rep movsd`).
- `Matrix3::zero` and `identity` (0x009d9330, 0x009d93a0).
- The `Vector3` statics `zero`, `one`, `unitX`, `unitY`, `unitZ`, `inf`/`nan` (folded), `minFinite` and `maxFinite` (0x009da920 to 0x009dab20).
- `Vector2::one` and `zero` (0x009d6a60, 0x009d6aa0).
- `CoordinateFrame()` at 0x009d9550: 160 calls.

To measure it cleanly, I compiled 40 affected App source files twice from the `build-g3d` commands, once with the old G3D headers and once with the new ones, and compared each function with PLAYER:
- Total masked differing bytes fell from 14,446 to 11,704. Mean similarity rose from 0.712 to 0.782.
- Byte-identical after the change: both `Region3` constructors, `Region3::init`, `Extents::express`, `Extents::toWorldSpace`, `Math::getWellFormedRotForZVector` and `CoordinateFrameBridge::fromAxisAngle`.
- Within 1 to 9 bytes: `GuiItem::getChildPosition`, `normalIdToMatrix3Internal`, `safeDirection`, `matrixTiltQuadrant`, `getAxisRotationMatrix`, `normalIdToVector3` and `Body::refreshCofm`.

**3. Upstream text, each change confirmed by PLAYER bytes.** I downloaded G3D SVN r30 in full to `3rdparty/_downloads/g3d-svn-r30-full`.
- **0007, `System`:** adds upstream's `m_appDataDir` string and the `LARGE_INTEGER` timer fields. That accounts for the class being 0x20 bytes bigger. It also restores the registry read of CPU speed in `init` and upstream `RegistryUtil`. `initTime`, `getStandardProcessorExtensions`, `init`, `System()`, `RegistryUtil::readInt32` (0x009e5d40) and its helper (0x009e5c70) are now identical.
- **0008, `GImage`:** upstream's PPM/PGM/PBM formats plus the fork's DDS and PVR values, which explains the two extra enum values. `resolveFormat` (0x009df070) and `stringToFormat` (0x009deea0) are identical.
- **0009:** upstream `BinaryInput::loadIntoMemory` (0x009db850) is identical.
- **0010:** upstream `prompt.cpp`; 11 of its 16 functions are identical (0x009e5570 to 0x009e5c20).
- 0006 also made `CoordinateFrame::lookAt` (both overloads) and `lerp`, `Quat::toRotationMatrix`, `Ray::set` and `Box::init` identical. The old `rayAABox` and `Vector3::ignore` rows turned out to be wrongly placed: those addresses hold `collisionLocationForMovingPointFixedAABox` and `Vector3::unitZ`.

All patches are staged and installed with `tools/lib/install_libs.py g3d`. `build-g3d` builds cleanly.
