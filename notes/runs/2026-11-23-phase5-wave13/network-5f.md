## Patterns proven

- `return flag ? userId < 0 : superSafeChat;` gives `cmp [ecx+0xc8],0; setl al` with no `xor eax,eax`;
  the if/return form with `getUserID() < 0` zero-extends first (getSuperSafeChat 0x00527600).
- Branch layout follows the `if` sense: getChatMode 0x00527650 is `if (!FFlag) return superSafe ?..;
  return isGuest() ?..;` (the false path falls through).
- A ternary straight into a `bool` signal argument (`sig(p ? prop.getValue(p) : false)`) keeps
  `push eax` in both branches; an if/else with two calls gives `movzx`/`push 0`, a bool local merges the
  calls (onChildChanged 0x005661f0).
- `p->find<T>()->f(x)` evaluates `x` first; 2013 wrote `T* t = p->find<T>(); t->f(x);` (Client::
  onServiceProvider: the `push 0` / `[esi+0xab0]` load after the find/create call).
- `/Od` `__try/__except(result = f(GetExceptionInformation(), true), EXCEPTION_EXECUTE_HANDLER)` reproduces
  byte for byte; reccmp leaves the `__sehtable$` push unpaired (98-99%), so such functions stay STUB until
  the generator adds `__sehtable$` rows (it has them for `__ehhandler$`).
